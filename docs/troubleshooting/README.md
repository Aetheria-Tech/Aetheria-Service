## 관통하는 규칙 몇 가지

여러 문서에 반복해서 나타나는 판단들입니다.

- **외부 시스템에 대한 되돌릴 수 없는 행위는 커밋 이후에** — S3 삭제, SSE 알림, Redis GEO 갱신이
  모두 `afterCommit`에 있습니다. (03, 08, 11)
- **트랜잭션은 넓게 걸수록 안전하지 않다** — 바깥 트랜잭션이 제약 위반을 커밋 시점으로 미루면
  그 위반을 잡아 처리하는 코드가 실행되지 않습니다. (01, 07, 11)
- **정합성의 최종 근거는 DB 제약이다** — 애플리케이션의 "조회 후 없으면 삽입"은 중복을 줄일 뿐
  거부하지 못합니다. (07, 11)
- **감지가 아니라 직렬화가 필요할 때가 있다** — 낙관적 락은 충돌을 알려 줄 뿐 기다려 주지 않습니다. (03)
- **끄는 쪽을 명시적 선택으로** — 기능 스위치의 기본값은 운영 동작이어야 합니다. (10)
- **이식성은 인터페이스가 아니라 의미가 결정한다** — 가시성 타임아웃에 기댄 재시도는 포트를 뚫어도
  옮겨지지 않습니다. 미리 만든 추상화가 감추지 못하는 것이 있습니다. (03, 12)

## 문서 규약

- 파일명은 `NN-영문-kebab-case.md`. 한글 파일명은 URL 인코딩되어 링크가 읽기 어려워집니다.
- 절 구성은 **상황 → 증상 → 원인 → 검토한 대안 → 해결 → 검증 → 남은 과제**. 쓸 내용이 없는 절은 생략합니다.
- 코드 인용은 5~15줄로 자르고 전체는 파일 링크로 넘깁니다. 문서가 코드 사본이 되면 금방 낡습니다.
- **라인 번호를 본문에 박지 않습니다.** 파일명과 메서드명으로 가리켜, 코드가 움직여도 문서가 틀리지 않게 합니다.
- 새 트러블슈팅을 추가할 때는 **README 요약과 이 디렉터리의 상세 문서를 함께** 갱신합니다.
